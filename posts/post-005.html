FreeRTOS 任务调度与消息队列实战

📅 2026-06-05 📂 嵌入式 🏷️ FreeRTOS, RTOS, STM32

为什么需要 RTOS？

裸机程序（超级循环）在处理多任务场景时，代码复杂度急剧上升。FreeRTOS 是一个轻量级的实时操作系统，提供了任务调度、消息队列、信号量、互斥量等功能，让多任务编程变得简单可靠。

任务创建

// 创建任务
xTaskCreate(
    vTaskLED,       // 任务函数
    "LED",          // 任务名称
    128,            // 栈大小 (words)
    NULL,           // 参数
    2,              // 优先级（数字越大越高）
    NULL            // 任务句柄
);

void vTaskLED(void *pvParameters) {
    while (1) {
        HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
        vTaskDelay(pdMS_TO_TICKS(500));  // 延时500ms
    }
}

消息队列

消息队列用于任务间安全传递数据：

QueueHandle_t xQueue;
xQueue = xQueueCreate(10, sizeof(SensorData));

// 发送端任务
SensorData data = {.temp = 25.5, .humidity = 60.2};
xQueueSend(xQueue, &data, portMAX_DELAY);

// 接收端任务
SensorData rxData;
if (xQueueReceive(xQueue, &rxData, pdMS_TO_TICKS(100))) {
    printf("Temp: %.1f, Hum: %.1f\n", rxData.temp, rxData.humidity);
}

任务优先级与调度

FreeRTOS 使用抢占式调度：任何时刻，就绪态中优先级最高的任务会获得 CPU。同优先级的任务通过时间片轮转。

⚠️ 注意：高优先级任务不要写死循环且不调用阻塞 API，否则低优先级任务会"饿死"。

总结

  • ✅ 多任务场景优先使用 RTOS，而非裸机超级循环
  • ✅ 任务间通信使用消息队列，避免全局变量竞态
  • ✅ 高优先级任务务必包含阻塞调用
  • ✅ 栈大小可以通过 uxTaskGetStackHighWaterMark() 分析优化
